## v0.1.0-preview.1 - 2026-08-08

### Release posture and provenance

- Release posture: unsigned public preview.
- Windows Authenticode: unsigned. No production Windows code-signing certificate was configured for this release.
- Checksum manifest: `SHA256SUMS` is published; verify downloaded files with `sha256sum -c SHA256SUMS`.
- OpenPGP checksum signature: absent because no production OpenPGP release-signing key was configured.
- Signed update manifest: absent because no production Ed25519 update-signing key was configured; unsigned update metadata is intentionally refused.
- Artifact attestations/SBOM: `sourceweaver-sbom.cdx.json` is published and GitHub artifact attestations are generated by the release workflow. Verify with `gh attestation verify <artifact> --repo dayflaree/sourceweaver` and `scripts/generate-release-sbom.py --validate-only sourceweaver-sbom.cdx.json`.
- Production signing boundary: #143 remains open because no production signing credentials or managed signing service were available for this preview.

### Preview limitations

- Hammer/Hammer++ open/save: not certified. Future issue #141 requires a runnable editor plus saved-VMF evidence.
- Native Windows Source compiler execution: not certified. Future issue #142 requires real native Windows VBSP/VVIS/VRAD execution evidence.
- Successful real game-runtime map load: not certified. Future issue #145 requires a successful real runtime map-load row.
- Rendered HLMV/HLMV++ model preview: not certified. Future issue #146 requires rendered external viewer evidence.
- Automatic installer execution, executable replacement, silent install, rollback, and update preference persistence are not implemented. Future issue #154 tracks that work.
- Windows artifacts are downloaded/hash/structure checked for this preview unless a separate real Windows interactive smoke environment is supplied. No Windows interactive desktop/installer smoke is claimed here.
- This release contains no proprietary game content, Source SDK tools, Hammer/Hammer++/HLMV/Crowbar/StudioMDL binaries, BSPs, MDLs, VTFs, VMTs, materials, sounds, maps, Steam data, private paths, private signing keys, or private user assets.

### Changed

- Merge translation now handles displacement `startposition`, texture-axis offsets, and known VMF ID reference remapping.

### Known limitations

- Linux AppImage GUI smoke evidence must be recorded per release on a clean Linux environment.
- Windows setup installers need interactive GUI smoke evidence outside silent CI install/uninstall.
- Release artifacts are unsigned unless Windows code-signing and OpenPGP release-signing secrets are configured.
- Automatic updates are intentionally disabled until signed update metadata and release signing enforcement exist.
- Third-party tools and assets stay unbundled unless the redistribution policy review records rights, provenance, attribution, checksum, update, and removal decisions.
- Real StudioMDL++ validation produced local evidence artifacts only; generated model outputs are not committed or redistributed.
- Hammer/Hammer++ open/save: not certified. Real editor certification remains future issue #141 and requires a runnable editor plus saved-VMF evidence.
- Native Windows Source compiler execution: not certified. Future issue #142 requires real native Windows VBSP/VVIS/VRAD execution evidence.
- Unsigned preview releases must explicitly say artifacts are unsigned and list OpenPGP/update-manifest/signing status. Artifact attestations and SBOMs do not replace Authenticode, OpenPGP, or update-manifest signatures.
- Real VBSP/VVIS/VRAD validation requires installed Source tooling or captured compile logs, and wrapper rows must stay labeled as wrapper evidence.
