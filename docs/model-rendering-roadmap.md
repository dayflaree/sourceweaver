# Native model rendering roadmap

Source Weaver's native model preview is currently metadata-only. It can inspect MDL headers, supported Source v44-v49 bodypart/model/mesh descriptor tables, local animation/sequence descriptor tables, material dependency tables, and companion VVD/VTX/PHY headers. It can also launch a user-provided HLMV-compatible viewer, but external viewer launch status is separate from native preview status.

## Decision

A native rendered model preview is **not in the current implementation scope**. Source Weaver should add it in explicit phases after redistributable fixtures and legal boundaries exist. The default model preview remains:

```text
Native model preview: metadata-only; no native mesh rendering, animation playback, skeleton visualization, PHY collision visualization, or HLMV parity.
```

## Scope by feature

| Feature | Current state | Future scope decision | Claim boundary |
| --- | --- | --- | --- |
| Preview cards/metadata | implemented | Continue improving from bounded MDL/VVD/VTX/PHY header parsing. | May show counts, names, warnings, material candidates, and companion status. |
| Static mesh rendering | not implemented | First native rendering target, but only after synthetic redistributable fixtures prove vertex/index extraction. | No static mesh rendering claim until VVD/VTX vertex/index extraction tests exist. |
| Material lookup | metadata only | Reuse `model-inspect --asset-root` material dependency resolution and the textured-preview sidecar/VTF roadmap. | Material presence is not textured model rendering or shader parity. |
| Animation playback | descriptor metadata only | Defer until skeleton pose evaluation and animation frame decoding are implemented. | No animation support claim. |
| Skeleton/bone visualization | not implemented | Possible intermediate mode after bone hierarchy/default-pose parsing is tested. | Bone names/counts are metadata; drawn skeleton requires renderer tests. |
| Collision/PHY visualization | probe only | Defer until VPHY collision solids/triangles are decoded with redistributable fixtures. | PHY section count is not collision visualization. |
| HLMV/HLMV++ rendered preview | external launch failure evidence only | Remains future certification issue #146. | No rendered HLMV/HLMV++ window claim until #146 records real evidence. |

## Parser strategy

Deep parsing should be staged and native only where test fixtures can be authored legally.

1. **Metadata card phase**: keep current bounded MDL/VVD/VTX/PHY header parsing and improve warnings/summary fields. This is already implemented.
2. **Synthetic static mesh phase**: extend native parsers only for the smallest Source-style model package needed to extract one rigid mesh from synthetic Source Weaver-authored MDL/VVD/VTX fixtures. Tests must verify vertex positions, normals, UVs, material index, index order, and bounds.
3. **Material preview phase**: optionally map mesh material indices to resolved material paths and preview sidecar textures after `docs/textured-preview-roadmap.md` sidecar rendering exists. VTF decoding remains optional and separately gated.
4. **Skeleton debug phase**: parse default bone hierarchy and draw line segments or axes. This can precede animation playback because it does not require frame decoding.
5. **Collision debug phase**: parse VPHY collision data only after a redistributable fixture and support matrix exist.
6. **Animation phase**: parse animation frame data, pose parameters, sequence blending, events, autolayers, IK, and bone controllers only with explicit support limits. This is a separate feature, not a natural consequence of sequence metadata parsing.

External tools remain optional. Source Weaver should not require Crowbar, HLMV, StudioMDL, Blender, or SDK tools for native renderer tests. External tool runs can provide supplemental evidence only when paths, versions, logs, inputs, outputs, hashes, and redistribution boundaries are recorded.

## Redistributable fixture plan

Allowed fixture sources:

- Source Weaver-authored synthetic binary fixtures generated by Rust tests or scripts.
- Source Weaver-authored QC/SMD source under a compatible license only if the compiled outputs are generated locally under `/tmp` and not committed unless redistribution rights are reviewed.
- Public fixtures only after `docs/third-party-redistribution-policy.md` approves exact origin, license, and redistribution scope.

Required fixture properties before renderer claims:

- no game content;
- no Steam paths;
- no proprietary MDL/VVD/VTX/PHY files;
- deterministic hashes;
- documented format fields covered;
- parser rejects truncated, oversized, inconsistent-checksum, and unsupported-version files;
- renderer fallback behavior recorded for missing companions/materials.

## UI plan

Current UI/CLI:

- CLI `model-preview` writes a metadata-only native preview report.
- Optional `--hlmv --launch` records user-provided external viewer process/log status.
- Desktop tooling can surface model-inspection/report fields, but does not render models natively.

Future UI modes should be explicit:

- **Metadata** — default current behavior.
- **Static mesh** — enabled only when a native static mesh extractor exists and fixtures pass.
- **Skeleton** — enabled only after default bone hierarchy drawing exists.
- **Collision** — enabled only after PHY/VPHY decoding exists.
- **External HLMV** — launch/status workflow only; rendered-window certification remains #146.

The UI should show a warning when mesh/material/animation/collision data is missing or unsupported and should fall back to metadata rather than producing misleading geometry.

## Exclusions for release wording

Do not claim any of these until implementation and validation exist:

- HLMV or HLMV++ parity;
- rendered HLMV/HLMV++ preview success;
- native textured model rendering;
- animation playback;
- skeletal pose or IK correctness;
- PHY collision visualization;
- VMT shader/proxy/VTF texture parity;
- bodygroup/skin/flex/expression correctness;
- runtime model appearance;
- game-runtime model appearance or runtime loading behavior.

## Validation requirements before claims change

Before a release can claim any rendered native model preview, evidence must include:

```bash
cargo test --workspace
cargo run -p sourceweaver-cli -- model-preview <synthetic.mdl> --json
python3 scripts/check-validation-claims.py --self-test
python3 scripts/check-validation-claims.py
```

A renderer-specific validation script should also generate or copy redistributable synthetic model packages under `/tmp`, render or extract deterministic geometry summaries, and record SHA-256 hashes. The script must state exactly which model features are supported and which are fallback-only.

## External references checked

- Source SDK 2013 `studio.h`, checked 2026-08-08: https://raw.githubusercontent.com/ValveSoftware/source-sdk-2013/master/src/public/studio.h . It defines `STUDIO_VERSION 48`, model limits, bones, hitboxes, attachments, LOD/bone usage flags, animation-related structures, and forward declarations for `vertexFileHeader_t` and optimized model strip headers. This supports staging static mesh, skeleton, collision, and animation work separately instead of treating MDL metadata parsing as a renderer.
